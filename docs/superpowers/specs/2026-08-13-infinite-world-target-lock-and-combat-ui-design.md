# 无限自然世界、目标锁定与战斗信息设计

## 背景与目标

当前地图以固定 `[0,1] × [0,1]` 世界和 `8×8` 网格为边界。高度场会钳制越界坐标，边缘山脊环负责遮挡世界尽头，分块调度器也只能在这 64 个区块内加载和回收。建筑、遗迹、祭坛、围墙与探索路径门既参与渲染，也通过静态或动态 OBB 阻挡玩家、普通敌人和首领。上述结构无法满足持续向外探索，也让地形与人工墙体限制了移动。

战斗侧已有软锁定、目标脚下环、普通敌人头顶血条、顶部目标焦点框、Boss 专属血条、延迟扣血层和伤害数字，但缺少玩家可控的手动锁定模式。多个表现层分别消费当前目标，普通敌人还会同时出现头顶血条和顶部焦点框，信息重复且群战容易拥挤。敌人接近行为也没有统一的最小间距和环形站位约束，可能贴住或重叠主角。

本次目标如下：

1. 将固定世界改为真正可持续扩展、确定性重建并按距离回收的无限程序化分块世界。
2. 移除所有地形墙体阻挡，以及全部建筑、遗迹、祭坛、围墙和路径门的视觉与碰撞。
3. 把依赖人工建筑或门的探索目标改为自然地标、自然节点交互或区域抵达触发，保证核心剧情仍可完成。
4. 增加自动与手动两种目标锁定模式，使攻击、投射物、镜头、锁定环和血条高亮始终指向同一目标。
5. 让敌人与 Boss 保持合理交战距离，多敌人围攻时为主角留出清晰空挡。
6. 采用已确认的 A「均衡清晰」视觉方案，美化普通敌人血条、Boss 血条和扣血动效，并控制同屏信息密度。

## 方案选择

采用“核心区保留 + 外围确定性无限分块”方案：

- 当前核心区继续承载手工自然地貌、出生点、NPC、主线、首领和一次性奖励。
- 核心区外使用世界种子与整数分块坐标确定性生成连续地形、生态、普通敌人和基础采集物。
- 相同种子和分块坐标必须生成相同内容；区块卸载并重新进入后布局不变。
- 核心区外不复制剧情、唯一地标、机关、Boss 或一次性奖励，避免内容语义重复。

不采用以下方案：

- 随机拼接现有地图块：实现较快，但重复明显，跨块地貌接缝与内容碰撞难以控制。
- 永久保存每个运行时随机区块：变化较多，但探索距离越远，存档会无上限增长。

## 无限世界坐标

### 坐标模型

世界位置拆分为两个稳定部分：

- `ChunkCoord { int64_t x, int64_t y }`：无限整数分块坐标，支持负坐标。
- `LocalPosition { float x, float y }`：当前分块内的归一化局部位置，规范化到 `[0,1)`。

每次移动后规范化局部坐标：局部坐标越过边界时，把整数差量转移到 `ChunkCoord`，再把局部坐标收回 `[0,1)`。游戏逻辑、存档、程序生成哈希和分块调度使用 `ChunkCoord`；渲染和短距离物理只使用相对玩家原点的局部浮点坐标，避免玩家走到超远位置后产生浮点抖动。

核心区映射到固定的原点区域。现有 `[0,1]` 内容坐标通过兼容转换落到该区域，不改变出生点、NPC、自然地标、任务触发区和 Boss 的相对空间关系。存档版本升级后，旧存档的位置字段按同一映射迁移到核心区；既有剧情、奖励、机关迁移状态和角色成长字段保持兼容。

### 无限高度场

`TerrainHeightfield` 不再钳制输入到 `[0,1]`，也不再叠加世界边缘山脊环。高度查询接收无限世界位置，并分两层计算：

- 核心区内继续应用现有手工地貌特征，但删除所有用于表现建筑基座、人工围墙或边界遮挡的特征。
- 核心区外使用连续的世界坐标噪声与确定性区域参数生成缓丘、浅水、草地和岩地。相邻分块必须在共享边界采样同一世界坐标函数，不能按块独立随机高度。

外围以可步行缓坡为主，不生成垂直墙状地貌。地表继续提供高度、坡度、水域和生态查询；跳跃、游泳和滑翔状态保持有效。核心区已有陡峭自然地形只保留视觉高度变化，不再进行水平阻挡、沿墙滑动或嵌入推出。角色经过较大高度差时，地面贴合使用有限速度的短距离平滑过渡，避免单帧弹高或跌落。

### 确定性内容生成

每个外围区块以 `worldSeed + ChunkCoord + contentKind` 的稳定 64 位哈希作为独立随机源，分别生成：

- 地形区域与地表混合参数；
- 植被实例；
- 普通敌人原型、数量和初始位置；
- 基础采集物类型和位置。

不同内容类型使用独立 salt，调整植被不会改变敌人布局。生成位置必须满足地表有限、非深水、坡度阈值与区块安全边距。外围敌人与采集物的短期击杀/采集状态只在玩家附近的有界缓存中保存，离开足够远或超过刷新周期后允许按确定性规则刷新；核心区剧情与一次性奖励继续永久保存。

## 分块预生成、加载优先级与回收

### 活动半径

以玩家所在分块为中心，根据有效画质档位请求方形活动区域：

- 高画质：`9×9`，即半径 4。
- 中画质：`7×7`，即半径 3。
- 低画质：`5×5`，即半径 2。

所有档位在活动半径外额外保留两圈缓存。区块离开缓存半径后，回收 GPU 网格、CPU 网格、植被实例、外围敌人、采集物以及与之关联的血条和目标引用。活动区块集合和内存占用必须有上限，不能随累计探索距离增长。

### 调度顺序

加载优先级依次为：

1. 玩家脚下区块。
2. 玩家相邻安全圈。
3. 相机前方和当前移动方向上的区块。
4. 活动区域其余区块。
5. 两圈保留缓存只保留已完成内容，不主动抢占活动区生成预算。

正常移动使用固定每帧 CPU 生成和渲染提交预算，不在渲染线程一次性生成完整活动圈。跨区或传送时，落点中心 `3×3` 分块同步准备完毕后才恢复画面，外围继续异步生成。若正常生成失败，使用相同坐标可重复得到的平缓草地区块兜底并记录日志，不留下裂缝或不可通行空洞。

### 渲染坐标

区块网格顶点以分块局部坐标生成，绘制时组合“目标区块相对玩家区块的整数偏移 + 局部位置差”。相邻 LOD 继续使用侧裙遮挡几何接缝；共享边界高度必须相等。雾、天空和远景不再依赖固定世界边界，远端由距离雾自然收口。

## 移除人工建筑、门与墙体

### 视觉与资源

从世界配置、生成头、ArkTS 资源清单、环境资源预载和 Native 渲染提交链中删除以下内容：

- 城镇、建筑、遗迹、祭坛与人工平台模型；
- 围墙、栅栏、门框与路径门模型；
- 仅为这些人工结构服务的装饰批次、碰撞盒和视觉地貌块。

渲染层不得保留透明、隐藏或远处 LOD 版本；验收口径是运行时场景中完全不存在这些模型和资源提交。NPC 迁移到附近经过坡度与水域校验的自然空地。

### 碰撞

玩家、普通敌人和 Boss 同时停用：

- 地形墙探测、沿墙滑动和嵌入推出；
- 静态建筑 OBB 碰撞；
- 动态探索路径门碰撞。

地面高度、水域、跳跃、游泳、滑翔与普通地表贴合继续生效。不保留“玩家可穿过、敌人仍被建筑挡住”的分叉规则。

### 探索与任务迁移

保留既有探索 ID 和已完成位掩码的含义，避免旧存档丢失进度，但把人工目标语义迁移为自然目标：

- 建筑或遗迹地标改为湖泊、巨树、特殊岩层、山丘或独特植被群。
- 机关改为自然节点交互，例如源质晶簇、古树根系、泉眼或发光岩脉。
- “打开路径门”改为抵达对应自然区域，或在激活自然节点后自动完成区域通行目标。
- 依赖门关闭状态的 HUD 文案与阻挡提示删除，替换为自然节点激活或区域抵达反馈。
- 主线、奖励发放、探索统计和存档恢复继续沿用原 ID 和完成状态，只改变标签、位置、目标类型和完成条件。

世界 schema 与构建期验证器需要阻止重新引入人工建筑、路径门碰撞字段或不可解析的人工目标依赖。

## 自动与手动目标锁定

### 统一控制器

新增单一 `TargetLockController` 作为目标状态的事实来源，输出：

- 当前目标 ID 与目标位置；
- `Automatic` 或 `Manual` 模式；
- 目标距离、镜头夹角和可攻击状态；
- 目标选中原因与是否应持续显示锁定标记。

攻击朝向、技能和投射物目标、轻度战斗镜头、脚下圆环、普通敌人血条高亮和快照字段都消费同一个控制器结果。禁止各系统自行再次选敌，避免视觉目标与实际命中对象不一致。

### 自动模式

没有手动锁定时，攻击输入触发自动选敌。候选必须存活、可攻击并位于有效攻击获取距离内，排序规则依次为：

1. 与主角的距离更近；
2. 位于镜头前方；
3. 当前已选目标仍有效时保持稳定；
4. ID 作为确定性最终排序。

自动目标从攻击开始至连招结束保持稳定；玩家停止战斗一小段时间后，脚下锁定环淡出。目标死亡、离开有效范围或随区块卸载时，控制器选择下一个有效候选；没有候选则安全清空。

### 手动模式与输入

在 `CombatControls` 增加独立锁定按钮：

- 单击：进入手动模式；首次锁定最近的有效敌人，后续单击按与主角距离从近到远循环切换。
- 长按约 `500ms`：解除手动锁定并恢复自动模式。
- 手动目标死亡或超过锁定维持距离：自动切换到下一个最近候选；没有候选时回到自动模式。
- Boss 与普通敌人统一参与距离排序，不强制抢占目标，玩家可通过循环切换到 Boss。

ArkTS 将单击和长按转换为两个独立 Native 输入事件，不复用攻击触控区域。长按只触发解除，不得在松手时额外产生一次单击切换。

### 锁定表现

自动和手动目标都在脚下显示金色圆环。手动锁定使用更稳定、稍清晰的呼吸强度；自动锁定随战斗活跃状态淡入淡出。圆环贴合目标脚底与体型缩放，保持现有元素染色混合，但金色锁定语义优先。锁定目标模型可保留克制的细轮廓，不增加遮挡角色动作的大型屏幕箭头。

## 敌人交战距离与围攻站位

每种敌人原型定义最小间距、理想攻击距离与最大追击距离：

- 普通近战敌人在攻击距离外沿停步，与主角保留约一个角色身位的视觉空挡。
- 远程敌人保持更远理想距离；主角逼近时优先侧移或后撤。
- Boss 根据碰撞体型扩大最小间距，避免模型遮挡主角或贴近相机。

敌人移动意图由“接近理想攻击点、避免进入主角最小间距、与邻近敌人分离、选择环形空槽”组合得到。多个敌人不能重叠或争抢同一站位。环形槽位以主角为中心，按目标距离和实体 ID 稳定分配，减少每帧跳槽抖动。

攻击动作允许短暂突进进入实际命中距离，但命中或落空后回到分配的理想位置。主角主动靠近时，敌人只通过自身后撤或侧移恢复间距，不对主角施加强制推开位移。敌人仍受最大追击距离约束，不能被无限拖离出生区块；目标或敌人区块即将卸载时先安全脱战。

## 战斗 UI 视觉规范

采用用户确认的 A「均衡清晰」方向，目标是明确、稳定且不遮挡动作。

### 普通敌人血条

- 血条位于模型头顶上方，锚点高度按敌人体型计算，并根据屏幕距离轻微缩放。
- 使用深色半透明圆角底、红橙渐变实际血量、浅金色延迟扣血层。
- 实际血量命中时立即缩短；延迟层短暂停留后平滑追赶，不瞬间跳变。
- 锁定目标增加细金边和小型锁定标识，不额外放大整条血条。
- 只显示当前锁定目标、最近受击目标及攻击范围内威胁最高的少量敌人；按距离、威胁和目标状态排序并执行同屏数量上限。
- 目标过远、位于镜头后方、死亡完成淡出或被场景遮挡时不显示或淡出。

已有顶部 `TargetFrame` 不再与普通敌人头顶血条重复显示。普通敌人以头顶血条为主；Boss 使用专属顶部血条。

### Boss 血条

Boss 血条固定在屏幕顶部安全区，展示名称、阶段、实际血量、延迟扣血层和吟唱进度。血条使用深色底和阶段元素色填充，保留现有阶段语义；延迟扣血使用浅金色，吟唱条位于主血条下方。布局需要避开刘海、任务 HUD、地图入口和系统安全区，并适配至少三种常见屏幕比例。

### 伤害数字

伤害数字从实际受击点上方弹出，执行快速放大、轻微上浮、少量横向偏移和渐隐：

- 普通伤害使用暖白色；
- 暴击使用金色并略大；
- 三种元素伤害继续使用现有元素色；
- 大额伤害、暴击和元素反应始终独立显示；
- 同一目标短时间连续的小额同类伤害合并或错峰显示。

伤害数字使用对象池与活动数量上限。投影结果钳制在安全显示区域；受击点位于镜头后方或超过显示距离时不创建数字，避免边缘堆积。

### 屏幕信息密度

血条发布侧先筛选有效候选，渲染侧只负责投影、边界钳制、淡入淡出和样式。Boss 条、普通敌人血条、伤害数字与锁定按钮必须在一屏内保持清晰，不与现有战斗技能按钮、摇杆、任务信息和小地图重叠。

## 数据流

### 世界流送

1. 玩家移动更新 `ChunkCoord + LocalPosition` 并发布相机朝向。
2. 世界网格计算活动半径、两圈缓存与方向优先级，产生加载/回收差量。
3. 调度器按预算生成确定性的地形、生态和外围内容。
4. 渲染线程提交完成区块，并以玩家相对原点绘制。
5. 超出缓存半径的区块连同外围实体和表现状态一起回收。
6. 快照只保存玩家世界位置、世界种子、核心区永久进度与有界的近期外围状态。

### 战斗与表现

1. ArkTS 把攻击、锁定单击和锁定长按作为独立输入事件传入 Native。
2. `TargetLockController` 根据模式、候选与当前状态生成唯一目标结果。
3. 战斗控制器、攻击执行器、投射物和镜头读取同一目标结果。
4. Loop 发布锁定环、血条、Boss 条和伤害数字所需的纯状态。
5. 渲染层进行世界到屏幕投影、同屏筛选后的动画与绘制。
6. 目标死亡、超距或区块回收时，目标控制器先切换或清空，再回收表现对象。

## 异常与边界处理

- 64 位分块坐标哈希必须覆盖负坐标、原点两侧、超远坐标和整数边界，不能依赖实现定义的有符号溢出。
- 生成任务若在完成前被回收请求取消，不得提交过期网格或实体。
- 传送落点若生成失败，使用确定性平缓兜底块；落点必须位于有限地面、非深水位置。
- 旧存档坐标无效或非有限时回退核心区出生点，并保留其他有效进度。
- 当前锁定目标随区块卸载时，不保留悬空 ID；手动模式按规则切换，无候选则恢复自动模式。
- 同屏血条、伤害数字和生成队列达到上限时按明确优先级丢弃低优先项，不能无界增长。
- 去除建筑与门之后，所有核心任务触发点必须经过可达性校验；不能只删除模型而留下无法完成的目标类型或文案。

## 测试策略

实现遵循测试先行。每个行为先写失败测试并确认失败原因，再写最小生产改动。

### 无限世界与流送

- 坐标规范化：正向、负向、跨多个分块和边界精确值。
- 高度连续：相邻区块共享边界高度、法线和水域判定一致。
- 确定性：同种子同坐标重复生成完全一致，输入顺序不影响结果。
- 超远坐标：大正负分块下高度和内容哈希有限稳定，渲染相对坐标无明显精度损失。
- 活动半径：高、中、低画质分别请求 `9×9`、`7×7`、`5×5`。
- 缓存回收：活动区外两圈保留，超过后网格、实体与表现状态一并释放。
- 优先级：玩家脚下、相邻安全圈和镜头前方早于其他区块。
- 传送：中心 `3×3` 完成后恢复，外围继续异步加载。
- 取消与失败兜底：过期任务不提交，失败生成平缓确定性区块。
- 旧存档迁移：旧 `[0,1]` 坐标映射到核心区，非法坐标安全回退。

### 自然世界与任务

- 世界布局生成结果不包含建筑、遗迹、祭坛、围墙、路径门或相关视觉资源。
- Native 渲染和 ArkTS 资源预载不再提交人工结构资产。
- 玩家、敌人与 Boss 更新路径不调用地形墙、建筑 OBB 或路径门碰撞。
- 原路径门、机关和建筑任务 ID 被自然节点或区域目标接管，旧完成位掩码恢复正确。
- 主线从出生到 Boss 可在无人工建筑情况下完成，所有自然目标位于干地或明确允许的水域且坡度可达。

### 锁定与敌人站位

- 自动模式按距离优先、镜头方向次级、当前目标稳定和 ID 最终排序。
- 单击首次手动锁定、连续单击按距离循环、约 `500ms` 长按只解除不额外切换。
- 手动目标死亡、超距或卸载时切换到下一个候选；无候选时恢复自动。
- Boss 与普通敌人统一进入候选，不强制抢锁。
- 攻击结算、投射物、镜头、脚下环和血条高亮读取同一目标 ID。
- 近战、远程与 Boss 分别满足最小间距；多敌人环形槽位稳定且实体不重叠。
- 攻击突进后回到理想距离；主角主动贴近不会被敌人强制推开。

### 战斗 UI

- 血条锚点随体型变化，远距缩放和屏幕边界钳制正确。
- 实际血量立即减少，浅金延迟层停留后单调追赶。
- 锁定、最近受击和高威胁目标按优先级进入同屏上限；过远、镜头后方和无效目标被过滤。
- 普通敌人不再重复显示顶部 `TargetFrame`。
- Boss 名称、阶段、血量、延迟层和吟唱条在安全区内布局。
- 连续小额同类伤害按窗口合并或错峰；暴击、大额伤害和元素反应保持独立。
- 伤害数字对象池达到上限时按优先级回收，不产生无界分配。

## 性能与设备验收

真机记录以下指标：平均 FPS、1% low、峰值内存、活动区块数、缓存区块数、生成队列峰值、单帧生成耗时和 draw call。最低目标为不持续两秒低于 30 FPS，推荐目标为平均 45 FPS。

若未达到目标，按以下顺序降级：

1. 降低外围植被实例密度。
2. 降低远距离区块细分与生态批次数量。
3. 缩短血条和伤害数字的可见距离或同屏上限。

不得缩小已经确认的 `9×9 / 7×7 / 5×5` 无空白活动范围。视觉验收覆盖晴天、复杂天气、连续跨区、快速转镜头、传送、群怪与 Boss 战，并在至少三种屏幕比例上检查安全区与信息可读性。

## 非目标

- 不在无限外围生成重复剧情、唯一地标、机关、Boss 或一次性奖励。
- 不引入永久保存全部探索区块的无界存档。
- 不增加联机同步、服务器持久化或玩家建造系统。
- 不重新设计现有角色技能、元素反应、战斗数值和 Boss 阶段机制。
- 不对主角施加由敌人触发的强制推开位移。
- 不用隐藏或透明模型代替人工建筑和门的彻底移除。
