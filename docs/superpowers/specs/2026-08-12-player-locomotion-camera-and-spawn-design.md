# 出生安全区、主角移动动画与自由环绕视角设计

## 背景与目标

当前体验存在三个相关但根因独立的问题：

- 出生点附近配置了一个 `sz_spawn_scout` 野外敌人。它会在玩家进入游戏后立即感知并追击，形成敌人持续贴身跟随主角的观感。
- 移动动画虽然已有姿态交叉混合，但低速 `walk` 与高速 `run` 共用 `RenderAnimation::Run` 意图。两者因移动比例跨阈值而更换实际 clip 时，现有混合时长函数看到的前后枚举相同，返回零秒，导致硬切。移动比例还取自瞬时摇杆幅度，与控制器平滑后的真实速度不一致。
- 相机已经支持围绕主角 360° 旋转，但主角停步且存在软锁定目标时会持续自动面向目标。玩家转动相机观察时，主角朝向也会变化，因此难以稳定看到主角正面。

本次目标是在不重做战斗锁定、输入系统和动画资源的前提下完成三项优化：

1. 出生安全区不再生成会追击玩家的侦察敌。
2. 主角从待机平滑进入走路，并在走路、跑步与待机之间稳定过渡。
3. 主角停稳后保持最后移动朝向，玩家可自由环绕相机查看正面。

## 方案选择

采用局部根因修复：

- 删除出生侦察敌的数据配置，而不是只把敌人移远或缩小感知范围。
- 以角色真实速度驱动步态，并让实际 clip 的变化决定是否启动姿态混合。
- 移除停步时软锁定目标对主角朝向的强制覆盖，保留软锁定的选敌、攻击路由、目标标记与战斗镜头距离。

不采用以下方案：

- 仅调整敌人位置、动画阈值或相机角度。这只能遮住症状，无法消除出生敌人追击、同枚举 clip 硬切和停步朝向覆盖。
- 新增显式锁定键并重做自由视角/战斗视角模式。该方案涉及 UI、输入和战斗交互，超出本次范围。

## 出生安全区

`assets/world/world.json` 继续作为野外刷怪布局的单一事实来源。删除完整的 `sz_spawn_scout` 刷怪区，并运行现有世界布局生成器同步 `native/generated/world_layout.gen.h`。

边界如下：

- 保留固定在远处的训练假人；它仍用于训练模式、三源反应和战斗教程。
- 保留西部、东部、中枢回廊、灰烬劣地和圣所高地的全部正常刷怪区。
- 不修改全局敌人感知半径、追击、仇恨联动、脱战或重生规则。
- 不以运行时特判 zone id 的方式隐藏敌人，避免 JSON 与 Native 行为分叉。

自动化验收应从生成后的真实世界刷怪定义构造 `WildSpawnSystem`，激活出生点所在分块并推进一帧，断言出生点安全半径内没有野外敌人；同时断言其他区域刷怪定义仍存在，防止误删全局敌人内容。

## 主角朝向与相机环绕

### 状态规则

- 有效移动期间，`PlayerController` 继续把摇杆输入按相机 yaw 映射到世界方向，主角朝向平滑追踪真实移动方向。
- 摇杆释放后，速度继续按现有减速曲线衰减；在角色完全停稳后保留最后朝向。
- 停步时拖动右半屏只改变相机 yaw/pitch，不修改主角朝向。
- 删除 Loop 中“停步时自动面向当前软锁定目标”的朝向覆盖。

### 保留行为

- `SoftTargeting` 仍按玩家位置、相机 yaw、候选距离和当前目标稳定性选择目标。
- 当前目标继续驱动攻击结算、技能释放方向、目标标记、敌人焦点框和探索/战斗相机距离。
- 移动时相机相对操控不变：向上推摇杆仍沿当前镜头前方向前进。
- 主角攻击、技能、闪避或首领演出已有的专用朝向逻辑不在本次重写；只移除停步常驻软锁定朝向。

### 验收

集成测试建立一个可持续软锁定的训练目标，先让主角形成明确朝向并完全停稳，再只输入相机旋转。相机 yaw 必须变化，主角 angle 必须保持不变，软锁定目标仍然存在。该测试同时防止未来为了目标锁定重新引入停步强制转向。

## 移动动画状态

### 真实速度比例

Loop 不再直接用 `intent.move.length()` 发布 `ActorRenderState.moveRatio`。移动比例由 `surface.player.velocity.length()` 除以当前地面目标最大速度得到，并钳制到 `[0, 1]`。

最大速度必须与本帧 `PlayerController` 使用的速度倍率一致：普通移动使用控制器基础速度，疾跑使用探索运动系统的疾跑倍率。为避免 Loop 复制私有常量，`PlayerController` 增加只读 `speed()` 查询；Loop 以 `playerController.speed() * 本帧有效速度倍率` 作为归一化分母。

若速度、基础速度或倍率不是有限正数，发布比例为零，动画安全回到待机。移动动画的播放速率仍使用现有 `RunPlaybackRate(moveRatio) * locomotionRateScale`。

### Idle / Walk / Run 步态

玩法层仍可保留现有 `RenderAnimation::Idle` 与 `RenderAnimation::Run` 大类，资源解析层将移动大类细分为可观察的实际 clip：

- `Idle`：速度归零且角色不再移动。
- `Walk`：真实速度比例处于低速区，优先使用 `walk`，兼容旧 KayKit 资产时继续支持 `Walking_B`。
- `Run`：真实速度比例进入高速区，使用 `run`。

走跑切换使用迟滞而不是单一阈值：

- 当前为 Run 时，比例降到 `0.30` 以下才进入 Walk。
- 当前为 Walk 时，比例升到 `0.40` 以上才进入 Run。
- `0.30–0.40` 区间保持当前步态。

首次从 Idle 进入移动时，以 `0.35` 为分界：低于 `0.35` 选择 Walk，达到或高于 `0.35` 选择 Run。所有常量集中在动画决策层，并由表格化纯函数测试锁定。迟滞只影响 clip 选择，不改变实际移动速度。

### 实际 clip 交叉混合

`SkinnedModel::update` 在 `desiredClip != currentClip` 时，基于前后实际 clip/步态决定混合时长，而不是只把 `animation.requestedAnimation` 与本帧 `requestedAnimation` 交给枚举级函数。

混合规则：

- `idle ↔ walk`、`idle ↔ run`、`walk ↔ run`：`0.15s`。
- 进入攻击、闪避、受击、施法等主动动作：维持 `0.12s`。
- 主动动作恢复到待机或移动：维持 `0.20s`。
- 进入死亡：维持 `0.25s`。
- 实际 clip 不变：不重启混合，也不重置当前播放时间。

状态需要记住当前移动步态，以便迟滞区间保持选择。该状态属于每个实体的 `SkinnedAnimationState`，不能放在共享模型资源上，否则多个角色会互相污染步态。

### 资源容错

- 主角重制资产有 `walk` 和 `run`，优先使用这两个语义 clip。
- 旧 KayKit 资产只有 `Walking_B` 时继续使用既有回退。
- 缺少所有 walk clip 时回退 `run`；缺少 run 时继续按现有链回退 `idle` 或首个可用 clip。
- 资源热更新或 revision 变化时，动画实例重置为 Idle 和未知步态，再由下一帧真实速度重新选择。

## 数据流

1. 输入层发布摇杆与相机拖动增量。
2. 相机先更新 yaw/pitch；`PlayerController` 用最新 yaw 计算世界目标速度并平滑得到真实速度。
3. 主角位置和移动朝向由真实速度更新；完全停稳后 angle 不再被软锁定覆盖。
4. Loop 以真实速度和当前移动倍率计算归一化移动比例，发布到 `ActorRenderState`。
5. 动画解析根据前一步态和移动比例做迟滞决策，选择 `idle`、`walk` 或 `run` 实际 clip。
6. 蒙皮动画实例检测实际 clip 变化，保留上一姿态并在规定时长内交叉混合。
7. 相机继续围绕玩家位置更新；停步拖动不会反向修改玩家 angle。

## 测试策略

实现遵循测试先行，每个行为先观察失败再写最小生产改动。

### 单元测试

- 真实速度比例：起步第一帧小于满速、持续输入趋近 1、释放摇杆后连续下降并最终为 0；疾跑倍率按本帧有效最大速度归一化。
- 步态迟滞：Idle 首次选择、Walk 在中间区间保持、Run 在中间区间保持、跨上下阈值才切换。
- clip 回退：`walk` 优先、`Walking_B` 兼容、缺失 walk 时回退 run。
- 混合时长：`idle→walk`、`walk→run`、`run→walk` 和 `walk→idle` 都是非零移动混合；同一 clip 不重启混合。
- 蒙皮姿态：使用现有 GLB fixture 验证 `idle→walk` 和 `walk↔run` 的中间帧同时包含前后姿态贡献，而非瞬时跳到目标姿态。

### 集成与数据测试

- 出生分块激活后，出生安全半径内无野外敌人；其他区域的刷怪定义仍被生成。
- 软锁定存在且主角停稳时，只转相机不会改变主角 angle，目标不会丢失。
- Loop 发布的 `moveRatio` 来自真实速度而非摇杆：起步首帧不得直接为 1，松开摇杆后的减速帧不得立即归零。
- 世界 JSON schema、布局生成器和生成文件一致性测试通过。

### 回归验证

- `test_player_controller`
- `test_render_animation`

- `test_camera`
- `test_camera3d`

若本机 HarmonyOS SDK 完整，再运行 HAP 构建。SDK 不完整时必须明确记录构建与真机验证待办，不以宿主测试替代。

## 设备验收

1. 冷启动后停留出生台地，主角周围没有敌人生成或持续贴身追击；远处训练假人与其他区域敌人仍正常存在。
2. 轻推摇杆，主角从待机平滑进入走路；继续推到大幅度时平滑进入跑步；在临界幅度小范围来回移动时姿态不抖动。
3. 松开摇杆，动画随真实减速平滑回到待机，不出现跑步硬切、走跑闪烁或脚步明显滑动。
4. 主角完全停稳后，围绕角色水平拖动一整圈，可稳定看到背面、侧面和正面；角色保持最后移动朝向。
5. 锁定训练假人或普通敌人时重复停步环绕，目标标记、攻击选敌和战斗镜头距离保持正常。
6. 移动中改变相机方向并推摇杆，主角仍沿屏幕相对方向移动，既有操控不回归。

## 非目标

- 不删除训练假人或其他区域敌人。
- 不调整敌人全局 AI、感知、攻击、仇恨或重生数值。
- 不增加锁定按钮、肩视角、第一人称或相机自动回正。
- 不新增或重制动画资源。
- 不改变战斗数值、角色移速、疾跑消耗、碰撞或存档格式。
