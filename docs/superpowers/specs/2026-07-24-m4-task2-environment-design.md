## 1. 目标

将当前以纯色地面和少量灰盒几何体为主的场景，改造成面向投资人演示的
“失落遗迹与裂隙”环境。Task 2 使用高细节写实 CC0 环境模型，建立可完整绕行的
开放遗迹环，并以中心首领裂隙作为持续可见的视觉地标。

本任务以演示画质优先，不限制新增资源包体；运行底线为常态不低于 30 FPS，
复杂首领区域不低于 24 FPS。

## 2. 已确认的产品与美术决策

- 场景方向：失落遗迹与裂隙。
- 资产许可：只使用 CC0 或等价公共领域资产，不接受仅“免费下载”或许可证不明确的资源。
- 资产组合：一个 CC0 主资产包，加少量用于补齐关键构件的 CC0 模型。
- 模型质感：高细节写实遗迹。
- 空间结构：环形开放遗迹，中心首领裂隙作为地标。
- 性能策略：演示画质优先，但保留 30/24 FPS 硬性验收底线。

## 3. 方案比较

### 3.1 分区合批场景（采用）

将静态环境整理为外围遗迹环、中心裂隙、边界背景和装饰等 3–5 个 GLB 批次。
批次共享少量材质，并根据摄像机位置和性能状态控制可见性。

优点：

- 能保留高细节模型，同时控制 draw call 和同时可见资源。
- 中心裂隙可独立调色、发光和扩展 Task 4 演出。
- 单批次失败时可以局部降级，不阻塞角色和战斗。

代价：

- 资产导入阶段需要统一比例、坐标、材质和纹理，并执行离线合批。
- 布局修改后可能需要重新生成对应场景批次。

### 3.2 独立可复用物件

每根石柱、墙体和碎石作为独立 GLB 实例布置。该方案调整灵活，但需要新增多模型
实例管理；环形开放场景容易产生过多 draw call，因此不采用。

### 3.3 单个完整场景 GLB

直接加载一个完整遗迹场景。该方案接入表面简单，但碰撞净空、区域配色、裂隙替换、
局部失败回退和性能降级都不灵活，因此不采用。

## 4. 架构与资源边界

场景划分为以下静态批次：

1. 外围遗迹环：石柱、断墙、拱门和主要可绕行结构。
2. 中心裂隙区：首领平台、圆形地面标记和红色裂隙。
3. 边界背景层：不可达的远景废墟、峭壁或巨型残柱。
4. 装饰层：碎石、残骸和不影响移动的小型视觉细节。
5. 动态标记层：需要调色、显隐或后续演出的少量独立物件。

每个批次使用稳定标识，不依赖容器迭代顺序。环境使用独立的静态模型管线；
玩家、敌人和首领继续使用现有骨骼动画管线。

CC0 原始文件必须保留以下证据：

- 资源名称和作者；
- 原始下载页；
- 明确的 CC0/公共领域许可证页；
- 下载日期；
- 原始文件 SHA-256；
- 项目内派生文件和原始文件的对应关系。

进入项目前统一右手/左手坐标转换、单位比例、UV、纹理格式、材质命名和资源路径。
静态环境合批不得修改角色、敌人或首领模型。

## 5. 空间组成

### 5.1 出生平台

位于遗迹环外侧。玩家进入场景时可以远眺中心裂隙，第一屏同时呈现角色、外围遗迹
轮廓和红色中心地标。

### 5.2 外围遗迹环

使用高细节石柱、断墙、拱门和碎石形成可完整绕行的主路径。主要转折点使用高大构件
提供方向感，避免依赖 HUD 导航。

### 5.3 探索节点

设置残破祭坛和坍塌营地两个短距离偏航目标，为环形路线增加构图变化和开放感。
Task 2 不为探索节点增加任务、奖励或剧情逻辑。

### 5.4 中心首领区

使用圆形地面标记、红色裂隙、更密集的破损建筑和独立光照形成视觉焦点。
中心区域保留足够战斗净空，不放置会干扰现有移动、闪避和 AI 的小型碰撞物。

### 5.5 边界背景

通过不可达远景废墟、峭壁或巨型残柱遮挡地图边缘。远景不参与战斗碰撞，
并作为性能降级时最先隐藏的批次。

## 6. 数据流与生命周期

资源数据流：

```text
CC0 原始资产
  → 许可证与 SHA-256 登记
  → 离线坐标/比例/材质规范化
  → 静态场景分区合批
  → ArkTS rawfile 资源字节桥接
  → Native 环境资产待提交状态
  → 有效 GLES context 下解析与 GPU 上传
  → Surface 按区域和性能状态渲染
```

启动时先显示现有程序化地面和基础几何体。环境 GLB 字节到达后，各批次独立进入
`pending / ready / failed` 状态。解析成功后按批次原子替换占位环境，避免半加载模型
闪烁。纹理上传、旧 GPU 资源释放和资源替换只允许在有效 GLES context 下执行。

环境模块不创建、销毁或恢复 NativeWindow/EGL 生命周期，只消费现有 Surface
提供的有效渲染上下文。

## 7. 光照与氛围

- 天空使用深蓝灰到冷灰的渐变背景，避免纯色清屏观感。
- 主方向光形成清晰石材轮廓和角色明暗面。
- 环境光保持角色和战斗按钮区域可读，不追求全黑阴影。
- 中心裂隙使用红色局部发光感，与玩家青色视觉形成对比。
- 外围遗迹使用冷灰石材，中心首领区提高红色和暗部对比。
- Task 2 不实现动态天气、昼夜循环或实时全局光照。

## 8. 性能与降级

验收底线：

- 常态场景：不低于 30 FPS。
- 复杂首领区域：不低于 24 FPS。
- 应用必须保持可操作且无 native crash。

运行时记录环境批次数、三角形数、纹理内存、draw call 和 FPS。连续低于性能底线时，
按以下固定顺序降级：

1. 隐藏边界远景装饰；
2. 降低碎石和小型装饰密度；
3. 切换环境低分辨率纹理；
4. 保留外围主体结构、中心裂隙、角色、敌人、首领和战斗特效。

降级不得改变战斗状态、AI、输入响应或角色动画。高细节模式为默认演示模式，
同时提供可复现的降级开关用于测试。

## 9. 失败处理

- GLB 特性或纹理格式不受支持时，日志包含批次名、资产名和明确失败原因。
- 单个环境批次失败只回退该批次，不影响其他环境和角色模型。
- 环境全部失败时回退到程序化地面和基础遗迹几何体，应用仍可启动和战斗。
- EGL、NativeWindow 或 context 异常继续使用现有恢复路径，环境模块不得自行重建窗口。
- CC0 证据不完整的资产在导入阶段直接拒绝，不进入构建产物。

## 10. 测试与验收

### 10.1 自动化测试

- CC0 清单字段完整性和 SHA-256 校验；
- 静态 GLB 网格、纹理和材质解析；
- 环境批次 `pending / ready / failed` 状态切换；
- 批次原子替换和单批次失败回退；
- 摄像机位置驱动的分区可见性；
- 固定的性能降级顺序；
- 降级不影响角色、敌人、首领和战斗状态；
- Task 1 动画、遭遇、战斗和桥接契约回归。

### 10.2 Pura 70 Pro 验收

- 出生点可远眺中心裂隙；
- 环形遗迹可完整绕行；
- 石材纹理、破损建筑、天空和光照层次清晰；
- 中心首领区与外围遗迹有明确颜色和构图差异；
- 常态不低于 30 FPS，首领区域不低于 24 FPS；
- 环境资源失败时可回退并继续战斗；
- 应用进程保持存活；
- 无 EGL、NativeWindow、Buffer 或 native crash 错误；
- 截图覆盖出生平台、外围遗迹、两个探索节点和首领区域。
