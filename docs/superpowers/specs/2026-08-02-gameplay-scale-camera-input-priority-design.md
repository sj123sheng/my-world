# 人物缩放、视角灵敏度与按钮输入优先级设计

## 目标

在不改变已验证的移动和朝向坐标约定的前提下，一次性改善三项真机操控体验：

- 主角、训练假人、普通敌人和 Boss 缩小为当前尺寸的约 `1/3`。
- 右半屏横向和纵向视角灵敏度从 `0.01` 降为 `0.0035`。
- 右下角战斗按钮的触摸优先于底层 XComponent，点按技能时不得同时触发移动或视角转动。

## 设计方案

### 人物模型缩放

`AssetProfile::forModel` 继续作为人物视觉尺寸的唯一配置入口。将三类资源档案的
`scale` 统一乘以 `1/3`：

- Player：`0.025 -> 0.008333333`
- Enemy：`0.022 -> 0.007333333`
- Boss：`0.045 -> 0.015`

训练假人和普通敌人共享 Enemy 档案，因此会保持一致；Boss 仍大于主角，不改变原有
角色层级。缩放只影响渲染矩阵，不改变玩家速度、世界坐标、攻击判定、软锁定或摄像机距离。

### 视角灵敏度

`CameraGestureConfig` 的默认 `sensitivityX` 和 `sensitivityY` 都设为 `0.0035`。保持横纵同比，
不引入加速曲线或设置页，避免扩大本次范围。所有现有的非法数值防护和增量消费逻辑保持不变。

### 按钮输入优先级

XComponent 仍是移动和相机的唯一生产输入源。`CombatControls` 根容器和按钮簇空白区保持
`HitTestMode.Transparent`，以便右半屏未覆盖按钮的区域仍可拖动视角。

每个真实可交互按钮的命中节点显式使用 `HitTestMode.Block`，包括普攻、闪避、三个源技能、
终结技以及调试菜单中的按钮。当按键命中时，该 pointer 不再下传给 XComponent；另一根手指已在
左侧移动时仍可继续移动，不影响多指战斗。冷却环保持透明命中，由其底下的按钮承担事件。

## 输入数据流

1. 按在战斗按钮上：ArkTS `Button` 阻断下传并执行 `pushAction`。
2. 按在右侧空白处：触摸穿透 UI，XComponent 将 pointer 分配为 Camera，原生相机消费拖动增量。
3. 按在左侧空白处：触摸穿透 UI，XComponent 将 pointer 分配为 Movement。
4. 同时按住左侧移动和右下按键：移动 pointer 留在 Native，按键 pointer 留在 ArkTS，互不抢占。

## 容错与边界

- 不屏蔽整个右下角矩形，避免按键之间的空白区丧失视角控制。
- 不向 Native 同步 ArkTS 按钮坐标，避免再次引入 vp/px 坐标契约和布局同步问题。
- 模型缩放不改变逻辑碰撞范围；本次产品目标仅是视觉尺寸。
- 灵敏度保持有限正数，不改变 `CameraGesture` 对无效坐标的现有处理。

## 验收与测试

### 自动化测试

- `test_asset_profile.cpp` 精确验证 Player、Enemy、Boss 的新 scale，并继续验证 Boss 大于 Player。
- `test_touch_controls.cpp` 验证默认 `CameraGestureConfig` 对固定像素拖动产生 `0.0035` 比例的 yaw/pitch 增量。
- `test_bridge_contract.mjs` 验证战斗按钮显式阻断命中，同时根容器和非按钮区继续透明。
- 运行与角色渲染、触摸路由、相机相关的现有回归测试，并完成签名 HAP 构建。

### 真机验收

- 确认主角、训练假人、普通敌人和 Boss 视觉尺寸约为修改前的 `1/3`，体型比例保持。
- 用相同距离水平、纵向拖动右半屏，视角旋转量约为修改前的 `35%`。
- 按住左侧持续移动时依次点击六个战斗按钮：行为触发，移动不中断，相机不偏转。
- 在按钮之间的右下空白处拖动：相机仍正常跟手。

## 非目标

- 不增加玩家灵敏度设置页。
- 不调整摇杆灵敏度、死区、玩家移速或转向速度。
- 不调整攻击距离、碰撞体、目标锁定范围或摄像机距离。
- 不改变已确认的移动、相机和模型朝向坐标约定。
