本仓库采用 HarmonyOS 官方包管理器 ohpm 进行依赖声明与解析，配合 hvigor 构建系统完成模块装配。整体依赖结构如下：

1. **顶层 oh-package.json5**：定义应用元信息（名称、版本、描述等），当前 `dependencies` 为空，说明应用本身不直接引入第三方 ohpm 包。
2. **entry 模块 oh-package.json5**：声明了唯一的依赖 `libnative_game.so`，通过 `file:./src/main/cpp/types/libnative_game` 以本地文件路径方式引用，属于本地私有模块。
3. **oh-package-lock.json5**：锁定文件记录了依赖解析结果，`registryType: "local"` 表明该依赖来自本地文件系统而非远程仓库，且启用了 `stableOrder` 保证安装顺序稳定。
4. **本地 NAPI 类型模块**：`entry/src/main/cpp/types/libnative_game/oh-package.json5` 将 C++ 原生库导出为 ETS 可引用的类型包，通过 `types: "./Index.d.ts"` 暴露 TypeScript 类型定义，供 ArkUI 层通过 N-API 桥接调用。
5. **构建系统集成**：`hvigorfile.ts` 使用 `@ohos/hvigor-ohos-plugin` 的 `appTasks` 作为默认任务集；`build-profile.json5` 配置了签名、SDK 版本（6.1.0）、ABI 过滤（arm64-v8a、x86_64）以及 CMake 构建路径。

**约定与约束**：
- 所有依赖均通过 ohpm 规范声明，未使用 vendor 目录或手动拷贝第三方代码。
- 原生 C++ 引擎通过 NAPI 以本地 ohpm 包形式暴露给 ETS 层，形成清晰的跨语言边界。
- 锁文件由 ohpm 自动生成，禁止直接编辑（文件中包含 `ATTENTION: THIS IS AN AUTOGENERATED FILE. DO NOT EDIT THIS FILE DIRECTLY.` 提示）。
- 当前工程未引入任何外部 ohpm 公共包，所有功能均自实现，依赖关系极简。
- C++ 第三方库（如 glm、cgltf、stb_image.h）以源码形式内联在 `native/third_party/` 目录下，不属于 ohpm 依赖范畴。
